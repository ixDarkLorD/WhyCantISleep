## Project

> Find out what's keeping you awake at night. Highlights the monsters blocking your sleep, explains every failed sleep, and adds a little bedtime fear.

> **CoolCatLib is one mod since 2026-10-14 (version 26.1.2-5):** Core and Canvas merged into **CoolCatLib**, mod id `coolcatlib`. Where the notes below say Core, Canvas, `coolcatcore`, `coolcatcanvas` or `coolcatlib-core-*` / `coolcatlib-canvas-*`, read them as this one mod.

A multiloader mod built on the author's libraries **CoolCatLib: Core** (`coolcatcore`, package `net.ixdarklord.coolcatcore`) and **CoolCatLib: Canvas** (`coolcatcanvas`, package `net.ixdarklord.coolcatcanvas`; required since 2026-10-13, at the author's request, for the visuals). The repository is private until the first release.

### Rules for every session

- **Never use Architectury API.** The Gradle toolchain is Architectury Loom, but the cross-loader runtime layer is CoolCatLib: Core only.
- **Never guess a CoolCatLib API.** Read its source first (see "CoolCatLib" below). If Core lacks something, say so and ask; don't invent it and don't silently work around it.
- **Build every loader before committing** (`gradlew build`), and fix errors before moving on.
- **Keep config names and defaults in sync with the mod page** (the list under "Config" below is the page's). Renaming or re-defaulting an option is a mod page change: ask first.
- Shared logic goes in `common`; loader modules hold only loader glue.
- **The mod is required on both the client and the server** (the author's decision, 2026-10-13, so the creature could be a real entity with its own model). Registry entries are allowed: the `lurker` entity type and the `mind` attachment exist. Sounds are unregistered `SoundEvent`s (`sound/WCISSounds`; the server names one by id, the client resolves it). `assets/whycantisleep/sounds.json` is **generated**: the author drops `.ogg` files into `assets/whycantisleep/sounds/` (see its `readme.txt` for the names) and `tools/gen_sounds_json.ps1` rewrites the file, using a sound's own files when present and a vanilla stand-in otherwise. Add a new sound in three places: `WCISSounds`, the script's table, the readme's table.
- Commits follow the user's `github-commit` skill: their identity only, no Claude attribution, and push only when asked.

## Build setup (copied from `../Starwoven-26.1.2` and `../GlazedMenu-26.1.2`; do not restructure)

- Build logic is **not in this repo**: `settings.gradle`, `build.gradle` and each module's `build.gradle` apply the remote scripts `ixDarkLorD/ModResources/gradle/v4/*.gradle`. Never copy or edit them; project tweaks go in the module's own `build.gradle`.
- Versions come from the catalog `net.ixdarklord:sharedcatalogs:${dependencies_catalog_version}` (`libs.*`): Minecraft 26.1.2, Java 25, loaders, Fabric API. Ask before hardcoding a version the catalog lacks.
- Architectury Loom **no-remap** (26.1 is unobfuscated: no mappings, `implementation`/`compileOnly` rather than `mod*` configurations), Gradle 9.4 wrapper.
- `gradle.properties` keys are read by the shared scripts by name; keep them. `mod_version` is a plain build number and the Minecraft version goes in front everywhere (`26.1.2-1`). `project_upload_debug=true` stays until the author says to publish.
- Each loader module needs its own `gradle.properties` (`loom.platform`, `platform_name`); the shared scripts fail without it. The root `CHANGELOG.md` is required too (the scripts read it at configuration time, and it is bundled into the jars).
- The CoolCatLib in Maven Local is published from the working tree of `../CoolCatLib-26.1.2` (republished 2026-10-14 for its Armature system; that build moved Canvas's asset namespace to `coolcatlib`, so shaders import `coolcatlib:sky.glsl`, `coolcatlib:vfx.glsl`, `coolcatlib:screen_effect.glsl`). Don't run Gradle with `--refresh-dependencies --offline`: it drops Loom's cached Minecraft metadata and the next offline build fails until one runs online.
- CoolCatLib: Core (`coolcatlib_version`) and MCP Bridge (`mcp_bridge_version`, `localRuntime`, dev runs only) come from **Maven Local**. If Core is missing there, every Gradle task fails: publish it from `../CoolCatLib-26.1.2` with `gradlew assemble publishToMavenLocal`.
- Machine-specific values (`curseforge_api_token`, `modrinth_api_token`, `mod_resources`, `build_jar_output_dir`) live in `~/.gradle/gradle.properties`, never in the repo.
- `build` also copies the loader jars to `build_jar_output_dir` and bumps the untracked `build_numbers.json`.

### Commands (PowerShell: `.\gradlew.bat`, Git Bash: `./gradlew`)

```
gradlew build                    # every loader; jars in <loader>/build/libs
gradlew :common:compileJava      # quickest compile check (or :fabric: / :neoforge:)
```

There are no tests or linters; verify by building and running the game. Both clients share `run/`. A running game locks `common/build/libs/*-dev.jar`: stop it before rebuilding, and when a server and a client run together start the server first and the client with `-x :common:jar`.

**Testing in the running game**: the `minecraft` MCP tools (MCP Bridge) drive a dev game: `game_start` (`loader`, `task`, `world`), `mc_command`, `mc_logs`, `mc_screenshot`, `mc_summon`, `mc_time`... After checks, `mc_leave_world` then `game_stop`. MCP Bridge exists for 26.1.2 only, so backports are checked by hand.

## CoolCatLib

Source on this machine, one checkout per Minecraft version: `../CoolCatLib-26.1.2` (branch `26.1.2`), `../CoolCatLib-1.21` (1.21.1), `../CoolCatLib-1.20.1`. Core is `core/{common,fabric,neoforge[,forge]}`; the public API is `core/common/src/main/java/net/ixdarklord/coolcatcore/api`. The API differs between versions (1.20.1 has its own `network.codec` and `CustomPacketPayload`, `ClientGuiEvents.RenderHud` takes `GuiGraphics, float`...), so read the checkout for the version being worked on. Canvas (`coolcatcanvas`, `canvas/` in the same checkouts, API under `canvas/common/.../coolcatcanvas/api`) is required too: `ScreenEffects.tint`, `CameraShake`, `WorldParticles` / `ParticleSpec` / `VfxMaterial` / `Curve` and `Easing`, all used from `client/fx/SleepEffects` and the HUD. Its camera shake and world particles exist on 26.1.2 only so far: check the 1.21.1 and 1.20.1 checkouts before backporting.

APIs this mod uses (`net.ixdarklord.coolcatcore.api.*`):

- `core.ModConstructor` / `ClientModConstructor`: `onConstructMod()` is where configs, payloads and events are registered (NeoForge collects payloads before common setup). `core.neoforge.NeoForgeModEntrypoint`.
- `config.*`: `Config.builder(MOD_ID, ConfigScope.CLIENT | SERVER)`, values as static `ConfigValue` fields, groups with `push`/`pop` in static blocks, `enumValue` (enums implement `EnumType.Displayable`), `color`, `intValue().range().slider()`, `enabledWhen`. A `SERVER` config is synced to clients on join and on change (`Config.isRemote()`, `ConfigEvents.SYNCED`). Names are translated as `config.whycantisleep.<client|server>.<group>.<key>` (`.title` for the config); tooltips fall back to the `comment`. Screens come from Glazed Menu when installed (`config.client.ConfigScreens`); Core has none of its own.
- `network.Network`: `registerClientbound` / `registerServerbound` (record payloads can derive their codec through `PayloadCodecs`), `sendToPlayer`, `sendToServer`, and `canPlayerReceive(player, type)`, which is how the server tells who has the mod. Clientbound handlers must be lambdas into a `client` package class so a dedicated server never loads it.
- `event.v2.common`: `PlayerEvents` (`JOIN`, `LEAVE`, `START_TICK`, `END_TICK`), `ServerTickEvents`, `ServerLifecycleEvents`, `BlockEvents.BREAK`, `EntityEvents.LOAD`. `event.v2.client`: `ClientTickEvents`, `ClientGuiEvents.RENDER_HUD`, `ClientPlayerEvents`. Each is an `EventInvoker` (`X.END.register(...)`).
- `registry.DeferredRegister` / `RegistryEntry` / `EntityAttributes` and `client.registry.EntityRendererRegistry` (the Lurker), `attachment.AttachmentRegistry` (`Mind`: saved, synced to its own player, kept through death), `event.v2.common.CommandEvents`, `platform.Platform`.

## Sides and sync

The mod is needed on both sides. The server is authoritative: it sends the failure reason and the exact blocking mobs, runs the sleep board and nudges, keeps each player's mood and lucidity, and its config overrides the client's. The client still recognises the game's own sleep messages by translation key and can redo the monster check itself (`SleepChecks.blockersOnClient`), a leftover from when client-only installs were supported; it is harmless and keeps the HUD working if a report is ever missed.

Config gating: every client option a server setting controls is declared `enabledWhen(<server value>)` in `WCISClientConfig`. Glazed Menu evaluates dependencies across configs, so the entry shows greyed out ("Depends on …") while the server has it off: that is the "locked" state. Code must read such options through `WCISConfigs.isEnabled(option)`, which walks the same dependency chain, never through `option.get()` alone.

## The sleep HUD

Sleep messages are not shown on the game's action bar. `GuiMixin` cancels the game's sleep lines (recognised by translation key in `client/hud/Explanations`) and `client/hud/SleepNotices` shows a card instead: a `SleepNotice` (kind, title, hint), whose kind gives the accent color, the icon (a vanilla item) and the sound and screen effect (`SleepEffects.onNotice`). The sleep board (`client/board/SleepBoard`), the cards and the mood and lucidity status share `client/hud/HudStyle`. The author first asked for the game's own tooltip look and then, on 2026-10-14, for textures of the mod's own: panels and bars are GUI sprites under `textures/gui/sprites/hud/` (a dusk plum card, outlined, shaded and shadowed like the gauges, and a bar track, nine-sliced by their `.mcmeta`; three fills; and the two status gauges, which the author asked on 2026-10-14 to look unlike the card: a round gold medal on a riveted round-ended track for mood, a rose diamond on a notched pointed track for lucidity, drawn at their own size) and drawn by `tools/gen_hud_textures.ps1`. Keep them in the game's manner (beveled pixel art, the chat's colors for text, vanilla items for the cards' icons, `PlayerFaceExtractor` for players); add a new panel there rather than drawing fills and gradients in code.

## The thing under the bed (`lurker/`)

Added at the author's request on 2026-10-13; every number is a first guess (`LurkerServer`'s constants).

- **What calls it** is low lucidity (`mind/`, below). Stages (`LucidityStage`): Uneasy under 75, Shaken under 50, Breaking under 25. Lying down in the dark costs 8 lucidity at once, in the light gives 6 back.
- **Uneasy and Shaken are client side** (`lurker/client/LurkerHaunt`), seen only by the player: eyes under dark beds and whispers; then the creature itself as a hallucination, a `LurkerEntity` added to the client's level only (never known to the server), standing in the dark or crawling out beside a bed the player uses, gone when looked at, approached or after 8 seconds.
- **Hunted is real** (`LurkerServer.summon`): a `LurkerEntity` comes from beside the player's last bed if it is near, else from the dark around them. It targets only its victim. Never in Peaceful (vanilla lets no mob target a player there; a Lurker that won't move in a test world is this).
  - **Watching** (how it starts; synced `HUNTING` false): it stands and stares. Its player's screen goes dark but for one light that falls from where the Lurker is (`Dark` and `Light` uniforms of the `dread` effect), spilling in from the screen's edge when it is out of view.
  - **Hunting**: the server starts it the moment the player looks at it (within about 21 degrees, in line of sight, for 5 ticks), walks into it or strikes it. It runs at about sprint speed.
  - **Ignored**: unlooked at for 25 seconds it leaves, stays away 40 seconds, and `LurkerServer` counts the snub. From the second snub in a row it **lures**: it calls out and the client turns the player's view slowly towards it (`LurkerPresence.pull`, faster per snub, slow enough to resist by turning away). Being looked at resets the count.
  - **Escaped**: hunting, a player who stays 14 blocks clear of it for 6 seconds has got away; it vanishes and stays away 40 seconds. It also vanishes in daylight or after 3 minutes. Killing it gives 35 lucidity back; if it kills its player, their lucidity is lifted to at least 45.
- **Opting out**: the client option "Scary content" off stops every frightening effect on that client and tells the server (`ScaryPreferencePayload`) to send no creature after that player (their mood and lucidity still move). The server option "Bed creature" turns it off for everyone. Creative and spectator players are left alone.
- **Model and textures** (CoolCatLib armatures since 2026-10-18, at the author's request): `tools/gen_lurker_armatures.py` writes `armatures/lurker_<kind>.geo.json` and `.armature.json` from the old vanilla models, laid out there part by part in vanilla terms (offsets, boxes, radians) and converted to Bedrock (rotations as (x, -y, -z) in degrees: vanilla's Y is down and the armature's up, which reverses turns about x and z on top of Bedrock's own x/y reversal; the first conversion used (-x, -y, z), which crossed the Flicker's horns, pointed the Stalker's down and would have opened jaws upward; `LurkerRenderer.turn` the same); every joint has a unique name the renderer moves it by (`tail_0..3`, `right_arm_lower`, `segment_0..4`, `right_leg_0`, `right_eye_pupil`, `right_eye_lid`...). Each eye is a glowing ball, a slit pupil that slides to where it looks, and a lid whose Y scale is how far it is shut. `tools/gen_lurker_textures.ps1` shares the box UVs (64x64 layouts drawn at 128x128, the Brute 128x128); change both together. The `.armature.json` names the skin and its glow texture (everything that glows: the eyeballs, red with a hotter heart, plus the veins and lit vertebrae). All motion is procedural: `LurkerRenderer` (an `ArmatureMobRenderer` picking the armature by kind with `.armature(...)`) ports each old `setupAnim` into a `JointModifier`, its `turn`/`move` helpers taking vanilla radians and Y-down pixels onto the pose; the body eases between three stances from `huntAmount` and its age: rising out of the ground, crouched and watching, reared up and hunting, plus the strike (`getAttackAnim`). A hallucination, and every Flicker, is drawn `.translucent` with a flickering `.tint`. The rest pose has the limbs straight (their lean is all in the motion), so the model viewer shows them so.
- **Presence** (`lurker/client/LurkerPresence`): any Lurker within 24 blocks drives the `whycantisleep:dread` Canvas screen effect (`post_effect/dread.json`, `shaders/post/dread.fsh`; uniforms `Pulse` and `Approach`): color drains and a ragged darkness closes in with nearness; while it closes the distance the view tightens and splits at the edges, and a quickening heartbeat flushes the edges red and jolts the camera. `tools/gen_arrow_texture.ps1` draws the HUD arrows.
- **Colors**: `lurker/LurkerPalette` holds the author's five-color sunset palette (2026-10-14, replacing "Electric Feel"): near-black, navy, maroon, crimson and red `#FF2D46`; the texture script, the particles in `SleepEffects` and the constants in `dread.fsh` repeat it. Keep the Lurker's skin, glow, particles and screen tints inside it (its teeth are the one derived pale tone). The glow is the armature's glow texture with a pulsing `.glow` strength (slow watching, fast hunting); the renderer also sets the pupils' aim (towards the local player, plus darting while it watches) and the blinks. `dread.fsh` leaves red undrained so the eyes stay red on a greyed screen.
- **Kinds** (the author's request, 2026-10-14): `lurker/LurkerKind` lists four, one entity between them and an armature each (the Stalker four spider's legs, the Flicker a legless floating wraith with long arms, the Brute a knuckle-walking hulk on a 128x128 sheet, the Leech a five-segment crawler with four mandibles; `LurkerRenderer` picks the armature by kind and moves it with that kind's motion, and the texture script has a `Paint-<Kind>` layout matching each armature's box UVs and sizes), told apart by a synced id (saved as `Kind`), attributes set in `LurkerEntity.setKind` (health, speed, damage, `Attributes.SCALE`, knockback resistance) and a skin pair each (`textures/entity/lurker/<kind>.png` and `<kind>_eyes.png`, all from `tools/gen_lurker_textures.ps1`). Stalker: the plain one. Flicker: translucent; hunting, every 3 s it teleports behind its player if they aren't facing it and it is over 5 blocks off. Brute: 1.4x, 60 health, slow; roars every 8 s within 14 blocks (Slowness II, Darkness, -2 lucidity). Leech: 0.65x, faster than a sprint, 2 damage; its bite gives Hunger II and Weakness, takes 4 mood and heals it 4. `LurkerKind.pick` weights them 40/25/20/15; `/whycantisleep summon [kind]` brings one; `/summon` takes `{Kind:"brute"}`. All numbers are first guesses.
- **Testing**: `/whycantisleep mood|lucidity [0-100]`, `/whycantisleep status` (every value behind them, for checking the rules; `/tick sprint 2400` runs twelve updates at once), `/whycantisleep summon` and `/whycantisleep ignored <0-9>` (operators). The Lurker needs steady camera control to test: the dev run's `pauseOnLostFocus` is off in `run/options.txt` so timed checks keep running when the window loses focus, and a hand on the mouse while the window has focus will look at it for you.

## The Dark Between (`between/`) — stage 1 of the author's dimension concept (2026-10-14)


**Name**: the dimension is called **The Dark Between** (the author's choice, 2026-10-17; it was the Lucid Deep, then briefly the Hollowmare). The code was renamed with it (2026-10-17): dimension id `whycantisleep:dark_between` (dimension, dimension_type, noise settings, skybox and sky shader `dark_between`), package `between` (was `deep`), `DarkBetween` (was `LucidDeep`, with `isBetween`), `BetweenProgress` (attachment `between_progress`), `BetweenClient`, `BetweenSkyClient`, lang keys `message/subtitle.whycantisleep.between.*` and `dimension.whycantisleep.dark_between`, and the generators `tools/gen_between_{blocks,structures,world,textures}` with `tools/between_structure_sizes.json`. Worlds made before the rename lose the old dimension's contents (`dimensions/whycantisleep/lucid_deep`). Call it the Dark Between in code, docs and anything players see.
The dream dimension the Lurkers come from. The author's concept (3 minion bosses and a lord, 12 creatures that some worn items make ignore you, loot worth exploring for, an abyss sky with floating debris, smoke, lightning between clouds and glowing lights, a square window to the dimension the player came from) is being built in stages. Stage 1 is the dimension itself and getting in and out; none of the creatures, bosses, gear or loot exist yet.
- **Data** (`data/whycantisleep/`): `dimension/dark_between.json`, `dimension_type/dark_between.json` (fixed time, the End's clock and timelines, no sleeping, fog and ash) and one biome, `the_shallows` (falling ash and crimson spores, soul sand valley sounds). The terrain, surface and decorations are written by `tools/gen_between_world.py` (run it after changing it; never hand-edit what it writes): asymmetric, lumpy floating islands from four noises of its own (`island_shape` through a vanilla shift, `island_mass`, `island_lift`, `ash_patches`, a tilt, base offset -0.74), topped with ashen moss and soil, veined dreamstone under ledges, and placed features (dead sleepwood trees, lucid blooms and thorns, broken pillars, wake crystals, hanging veins and lanterns under ledges). 26.1.2 has no `random_patch`: patches are `simple_block` with count/random_offset/predicate placement, and `environment_scan` takes at most 32 steps.

Haunted house (two storeys, porch, cellar), Garden of Despair (the author's reference was a walled hedge maze: 14-high dreamstone walls, detailed at the author's request 2026-10-14: a battered polished plinth, pillar pilasters every 10 blocks with framed panels between them (engraved rune band, an arrow slit or carved eye at the middle), an engraved frieze under a corbelled cornice carrying the walkway out over the face, merlons 3 wide / gaps 2 capped with polished slabs, an inner rail; 9x9 corner towers and 5x5 gate towers with their own bands, corbelled crowns, battlements and lanterns; breaches; an arched gate with corbels, keystone and rune band on each side; outside, stair bases and capitals on the pilasters and lanterns hung from fence brackets; inside, a rune frieze and corbels over the maze. ## Grounded animation (`tools/rig_pose.py`)
- `rig_pose.py` poses a generated armature exactly as CoolCatLib does (checked against the viewer to 0.01 px): `Rig(bones).world(pose)` and `Rig.at(world, bone, point)` (file coordinates: rotations `Rz(-z) Ry(y) Rx(-x)`, about the pivot, rest + pose; the position channel moves the bone), `sample(clip, t)` (keyframes with Catmull-Rom, and the generators' Molang: math.*, q.anim_time, one `?:`), `solve(rig, pose, [(bone, axis)], error)` (a coordinate search; it records which bones `error` reads and poses only those after), `lowest`, `settle(rig, clip, contacts)` (samples a clip and moves `root` so its lowest contact is on y = 0 at every sample; returns dense linear keys) and `report`. `settle` on a loop runs its `after` once round first (so adjustments that carry from sample to sample, like the scythe's, start as they end) and sets the last pose to the first. `seamless(clip)` snaps every `q.anim_time * k` in a looping clip's Molang (chained factors multiplied) to a whole number of cycles over its length: gen_mobs `write_mob`, gen_gardener and gen_dreamer_anim run it on every clip, since a walk written at one cycle per second in a 0.8 s clip jumped each loop.
- The Gardener (`gen_gardener.py` `grounded()`): every clip is settled on the ground (idle, walk and run used to sink 3-7 px). `contacts()` lists what may touch it (soles, toes, heel spurs, knees, shins, hands, claws, elbows, head, shoulders, hips, scythe). Kneeling (`_kneel`: knee on the ground, shin lying back, toes tucked; the other leg `_plant_leg` IK'd to an ankle 5 up and the foot turned flat), the staff (`_plant_scythe`: arm and scythe solved so its foot stands near-upright on the ground), claws on the ground (`_claws_down`), a two-handed grip (`_grip_shaft`: the left palm onto the shaft, searched from several starts and grip points, the chest turning a little), the blade striking (`_blade_down`), the scythe giving way to the ground (`_scythe_rest`, after the body is set: it must never prop the body up) and both knees (`_kneel_both`). Key poses become clips (`_keys`, every bone keyed so action clips override the base layer whole) and are settled; standing clips (`swing`, `deflected`, `roar`) are filled with idle's first pose and their ends set to it. Every clip starts and ends on idle's first pose (checked: 0.0 px jumps between clips that follow each other), and `GardenerEntity.begin` fades 0.15 s into each. Clips: `dormant` (on its left knee, bowed over the staff, claws down), `awaken` (head lifts, heart beats, a push up on the staff with both feet planted, stands tall and spread, settles), `stagger` (thrown back a step, down on its knee, ribs flung open), `staggered` (kneeling on the staff, head lolling, heart throbbing), `recover` (a heave on the staff, rising), `heart_struck` (arched back on its knee, ribs slam, doubled over, rising), `slam` (two-handed: raised high behind its head, a lunge and the blade driven into the ground at 0.75 s, held, drawn back) and `death` (3.4 s, held: convulsion, a stagger back, both knees, the scythe slipping to the ground, swaying, a collapse forward on its face; the entity is removed at 78 ticks). **The body is set on the ground by its body only (`BODY`, the contacts without the scythe)**: hanging from the fist the scythe reached lower than the feet, and counting it floated the feet 3.5 px at the ends of every clip (up to 40 px mid-clip). The scythe gives way to the ground instead: `_ScytheClear` (passed to `settle` as `after`) turns only the scythe, by as little as clears it, carrying the correction from sample to sample and easing it off a few degrees a sample; key poses held close to the ground use `_scythe_clear_hold` (the angle nearest the hold, no twist, that clears); `_keys` unwraps each turn to the nearest equivalent of the last key's (300 after 165 is -60, or it spins the long way through the ground); and `_patch_scythe` mends each settled clip, inserting a cleared sample wherever the scythe would pass through the ground between two. Checked every 0.005 s: the body within 0.5 px of the ground in every clip, the scythe never more than 0.3 px into it (one in-between frame of `deflected`, 0.8). Generating takes about two minutes (the searches).

## Boss combat (`combat/`, souls-like; 2026-10-19)
- `BossCombat` is a component a boss owns (`new BossCombat(this, PROFILE, COMBAT_DATA)`, the boss implementing `CombatBoss`): **posture** (worn down by blows, `hitPosture` per damage, and by its own blows parried, `parryPosture`; steadies at `regenPerTick` after `regenDelay` unhurt), its guard **breaking** at max posture into a **stagger** (`staggerTicks`, hurt `staggerDamage` times harder), **parries** (`strike(level, target, BossAttack, source, damage)`: a target raising anything with `BLOCKS_ATTACKS` within `parryWindow` ticks, facing the boss, takes nothing; `Parry.parries`), and **critical strikes** (while staggered, a player's direct melee blow whose look passes within the boss's `CriticalPoint` radius, from in front and within `criticalReach`: the blow x `criticalMultiplier` + `criticalBonus`, and the striker plays `criticalClip` (a clip of the player armature `dreamer`, on its `combat` layer, via `ArmatureControl.play`). Blows on the boss go `incoming` (stagger multiplier, critical detection) -> `super.hurtServer` -> `landed` (posture pressed, or the critical strike's aftermath, only if the blow landed). `CombatProfile` (builder) holds the numbers; `BossAttack.of(name).parryable(..).parryPosture(scale)`; `CombatData.define(Class)` the synced posture (0-1) and staggered flag (define in a static field, `COMBAT.define(builder)` in `defineSynchedData`).

## Mood and lucidity (`mind/`)

**Lucidity is what was first called sanity**: the author asked for a name of the mod's own on 2026-10-14. Use "lucidity" everywhere (code, texts, commands, files); the stages read Lucid, Hazy, Clouded, Unravelling to the player, though the enum constants are still `STEADY`, `UNEASY`, `SHAKEN`, `BREAKING`.

Added at the author's request on 2026-10-14, replacing the earlier "dread" number; the same day the author cut it from three numbers (mood, lucidity, guilt) to **two bars: mood and lucidity**. Guilt is no longer a stat: a guilty act costs lucidity at once and weighs on mood for a while. Don't bring a third number back. Every number is a first guess (`MindServer`'s constants). The author's rule: **the routine must not be harsh**. Ordinary play (sleep, eat, go outside) keeps a player steady; doing varied and kind things improves on that. Don't add needs that turn it into a checklist.

- **`Mind`** is one immutable record in a synced player attachment (saved, sent to its own player, kept through death): `mood` and `lucidity` (each 0 to 100), the three needs `rest`, `food`, `outdoors` (0 to 1), `cheer` and `strain` (0 to 25, fading), and the recent `foods`. Change it only through `Mind.update`.
- **Mood** (`MindServer.update`, every 10 seconds): steps by 1 towards `25 + 55 * (rest 40% + food 30% + open sky 30%) + cheer - strain + 5 with company`. Levels: `MoodLevel` (Miserable under 25, Gloomy under 40, Flat under 55, Content under 75, Cheerful).
- **Lucidity**: +0.2 an update while mood is Content or better, 0 while Flat, -0.12 Gloomy, -0.25 Miserable. Lying down in the dark -8, in the light +6; waking rested +3; feeding an animal +0.5.
- **Guilty acts** (`MindServer.onGuiltyAct`): the cost comes off lucidity at once and 60% of it is added to strain. Killing a villager 15, one's own pet 18, another's pet 12, an iron golem 6, a baby animal 5. Between players only when unprovoked: the victim has not struck the attacker in the last 30 seconds (1.5 a hit, 20 a kill; server option "PvP guilt").
- **Each limits the other** (the author's request, 2026-10-14): mood can't climb past `Mind.moodCeiling()` = `58 + lucidity * 0.56` (no limit from 75 lucidity up), and lucidity can't recover past `Mind.lucidityCeiling()` = `40 + mood * 0.8` (no limit from 75 mood up); a value above its ceiling comes down to it. The floor of 58 on mood's ceiling is deliberate: it is still Content, so lucidity can always begin to recover. With a floor of 45 a player at the bottom of both stayed there for good (seen in a test). The closed-off part of each bar is drawn striped, behind a limiter line.
- **Hooks** (Core has no events for these, so common mixins): `FoodPropertiesMixin` (eating), `AnimalMixin` (feeding an animal), `LivingEntityMixin` (kills), `ServerPlayerMixin` (lying down, waking, being hurt, dying).
- **Client**: `client/mind/MindHud` shows a badge just under the crosshair while mood is Flat or worse (`MoodLevel.isUnstable`) or lucidity below Steady, and a card (`SleepNotices`) the moment lucidity drops a stage or mood drops to Gloomy or worse. `client/mind/MindStatus` draws each as a gauge above the inventory (`InventoryScreenMixin`): its medal with the icon on it and its bar in the track, with tooltips. The crosshair badges are the same medals: they swell in when a level drops, then rest faint (mild levels) or beat (bad ones). Each bar is three sprites (the author's reference, 2026-10-14: chunky arcade bars): the track (outline and empty blocks), the fill stretched to the value, and the frame over both (outline, block seams, glints); what the other bar closes off lies behind a limiter line under dim diagonal stripes (`*_limit`, tiled), and a slanted glint crosses the fill. Under each bar hangs a plaque (`*_sign`, a nine-slice board of its own on two chains, drawn with its text at 0.75 scale) with its reading, `<level> <value>` (`gui.whycantisleep.mind.reading`). The message card wraps its text at 124 wide, with its icon in a slot and a rule between title and hint. Icons: `tools/gen_mind_icons.ps1`.
- Creative and spectator players are left out; the server option "Mood and lucidity" turns it all off.

## Code conventions (from the author's other mods)
